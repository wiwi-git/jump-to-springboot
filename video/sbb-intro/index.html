커밋 000~090 · 태그로 그 시점 코드를 열 수 있어요
점프 투 스프링부트로 SBB,
질문 답변 게시판을 만들었습니다.
교재 그대로 만든 것과,
그중 무엇을 왜 개선했는지 소개합니다.
작업 방식은 단순해요.
교재 섹션마다 먼저 교재 그대로 구현하고,
섹션을 마치면 강사 수업의 방식으로 개선 커밋을 따로 만들었어요.
커밋 하나에 작은 작업 하나,
그리고 커밋마다 같은 번호의 태그를 달았어요.
그렇게 쌓인 커밋이 91개.
교재 구현 64개, 개선 24개, 설정 3개예요.
교재는 Spring Boot 3.x, Java 19~20,
Groovy 빌드 기준이에요.
이 프로젝트는 처음부터 강사 환경인 Spring Boot 4.1.2, Java 25,
Kotlin DSL을 썼어요.
개선 커밋에 버전 차이로 생긴 수정이 섞이지 않게 하려는 거예요.
버전이 달라서 교재 코드가 그대로 안 되는 곳도 있었어요.
spring-boot-starter-web은 spring-boot-starter-webmvc로 이름이 바뀌었고,
Spring Security 7에서는 AntPathRequestMatcher가 삭제됐어요.
이런 곳은 동작에 필요한 최소한만 고치고,
커밋 본문에 교재와 차이로 남겼어요.
먼저 교재로 만든 것부터 볼게요.
질문 목록과 상세, 답변,
질문 등록과 입력 검증, 페이징을 만들고,
Spring Security로 회원 가입과 로그인을 붙였어요.
이 화면이 질문 목록이에요.
한 페이지에 열 개씩,
아래에 페이지 번호가 있고,
오른쪽 위에 검색창이 있어요.
로그인하면 글쓴이가 기록되고,
내가 쓴 글에만 수정과 삭제 버튼이 보여요.
추천 수는 배지로, 내용은 마크다운으로 렌더링돼요.
마지막으로 제목, 내용, 글쓴이,
답변까지 한 번에 찾는 검색을 만들었어요.
여기까지가 교재 1장부터 3장 검색까지예요.
이제 개선이에요.
첫 번째는 설정과 데이터베이스.
교재는 설정을 한 파일에 몰아 두고,
테스트도 개발 DB를 같이 써요.
그래서 테스트가 개발 데이터를 넣고 지우고,
삭제 테스트는 두 번째 실행에서 실패했어요.
개선 후에는 프로필로 나눠서,
개발은 프로젝트 폴더의 파일 DB,
테스트는 메모리 DB를 써요.
테스트가 끝나면 DB도 사라지니,
몇 번을 돌려도 같은 결과가 나와요.
같은 생각으로 몇 가지를 더 나눴어요.
타임리프 캐시는 개발 프로필에서만 끄고,
개발 DB가 비어 있으면 샘플 데이터를 만들어요.
SQL 로그에는 물음표 자리에 들어간
바인딩 값과 트랜잭션의 시작과 끝을 찍어서,
어떤 메소드가 어떤 쿼리를 실행했는지 직접 볼 수 있게 했어요.
두 번째는 JPA 엔티티예요.
@ManyToOne은 기본값이 즉시 로딩이라,
답변을 조회하면 질문도 항상 같이 조회돼요.
강사 방식대로 LAZY를 걸어서,
질문을 실제로 쓸 때만 조회하게 했어요.
답변 리스트도 빈 리스트로 초기화해서,
새로 만든 질문에 답변을 넣을 때
널 포인터 예외가 나지 않게 했어요.
답변 저장도 바꿨어요.
교재는 답변에 질문을 넣고 답변 리포지터리로 저장해요.
DB에는 들어가지만, 이미 꺼내 둔 질문의 답변 목록에는 새 답변이 없어요.
관계의 한쪽만 맞춘 거죠.
개선 후에는 질문의 addAnswer 한 번으로 양쪽이 맞춰지고,
cascade PERSIST가 트랜잭션이 끝날 때 답변을 함께 저장해요.
삭제도 질문 쪽에서 해요.
교재처럼 리포지터리로 지우면,
메모리에 올라온 답변 목록에는 지운 답변이 그대로 남아요.
개선 후에는 deleteAnswer로 목록에서 빼기만 하면,
orphanRemoval이 고아가 된 답변을 커밋 때 지워 줘요.
세 번째는 폼과 보안이에요.
교재의 @NotEmpty는 길이가 0인 값만 막아서,
공백만 넣은 제목이 저장되고 목록에 빈 링크가 생겼어요.
@NotBlank로 바꿔서 보이는 글자가 있어야 통과하게 했어요.
폼 클래스는 record로 바꿨어요.
setter가 필요 없는 불변 객체라 코드도 짧아져요.
교재는 로그아웃, 삭제,
추천을 GET 요청으로 보내요.
그런데 Spring Security는 GET 요청에는
CSRF 토큰을 검사하지 않아요.
그래서 다른 사이트에 <img> 태그 하나만 숨겨 둬도,
그 페이지를 연 글쓴이의 질문이 삭제될 수 있어요.
그래서 셋 다 타임리프 폼으로 바꿨어요.
타임리프가 토큰을 자동으로 넣어 주고,
삭제는 hiddenmethod 필터로 DELETE 요청이 돼요.
그 결과, 삭제 요청은 이렇게 걸러져요.
GET으로 보내면 405,
토큰이 없으면 403,
다른 사용자가 보내면 400,
글쓴이가 토큰과 함께 보낼 때만 삭제돼요.
네 번째는 테스트예요.
교재는 테스트 하나를 지우고 다시 쓰면서 진행해서,
지난 단계의 테스트가 남지 않아요.
개선 후에는 모든 단계의 테스트를 메소드로 남기고,
@Transactional로 테스트마다 롤백해요.
그래서 실행 순서와 상관없이 매번 같은 데이터에서 시작해요.
섹션을 마칠 때마다 MockMvc로 화면 요청도 테스트했어요.
테스트는 2개에서 시작해서 53개가 됐어요.
그리고 테스트가 정말 문제를 잡는지,
코드를 잠시 되돌려 실패하는 것까지 확인했어요.
예를 들어 CSRF를 끄면 보안 테스트 2개가,
검색 쿼리에서 DISTINCT를 빼면 검색 테스트가 실패해요.
작은 개선도 있어요.
부트스트랩은 파일 대신 cdnjs 주소로,
글꼴은 프리텐다드로 바꿨어요.
브라우저 탭 제목은 페이지마다 다르게,
템플릿에는 네임스페이스를 선언해서 편집기 경고를 없앴어요.
정리할게요.
프로필로 개발과 테스트 DB를 나눴고,
엔티티는 LAZY와 질문 쪽 연관관계 관리로 바꿨어요.
폼은 @NotBlank와 record로,
상태를 바꾸는 요청은 토큰이 있는 폼으로 바꿨어요.
그리고 53개의 테스트로 이 동작들을 고정했어요.
코드와 커밋 기록은 깃허브 저장소에 있어요.
봐 주셔서 감사합니다.
